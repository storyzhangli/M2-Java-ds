## 5. TraceId 行为

### 5.1 Header

| Header | 方向 | 行为 |
|---|---|---|
| `X-Request-Id` | 请求/响应 | 兼容既有字段；有效值复用，缺失/非法时生成 |
| `X-Trace-Id` | 请求/响应 | D21 响应别名；值与 `X-Request-Id` 相同 |

`X-Request-Id` 优先；没有时也可以从 `X-Trace-Id` 接收相同语义的值。

### 5.2 合法性

外部 ID 必须：

- 长度 1–64，默认最大长度可配置。
- 首字符为字母或数字。
- 仅包含字母、数字、下划线和中划线。

非法、超长或含换行/NUL 的值不“清洗后继续使用”，而是生成新的 32 位无横线 UUID，防止日志注入和伪造链路。

### 5.3 传播边界

- 请求线程：写入 MDC `requestId`。
- 同步模型调用：直接从当前 MDC 取得。
- 流式模型调用：在 Flux 组装时从请求线程捕获 TraceId，异步回调只使用捕获值。
- `MODEL_CALL` 写日志时会显式临时恢复日志前缀中的 TraceId，随后恢复当前线程原 MDC。
- 请求结束由 `TraceIdFilter.finally` 清理 MDC。

该 TraceId 不是跨服务 W3C traceparent。

## 6. 脱敏模型调用记录

### 6.1 日志位置

- Logger：`MODEL_CALL`
- 文件：`logs\d21\d21-access.log`
- 格式：单行 JSON
- 每个逻辑模型调用只有一条终态记录。

### 6.2 字段白名单

| 字段 | 说明 |
|---|---|
| `event` | 固定 `MODEL_CALL` |
| `traceId` | 当前请求本地关联 ID |
| `callId` | 单次逻辑调用随机 ID |
| `provider` | `deepseek` / `offline-mock` |
| `model` | 实际模型标识 |
| `callMode` | `SYNC` / `STREAM` |
| `startedAt` / `finishedAt` | UTC ISO-8601 时间 |
| `elapsedMs` | 单调时钟测得的模型调用耗时 |
| `status` | `SUCCESS` / `ERROR` / `CANCELLED` |
| `errorType` | 异常类简单名，不含 message |
| `firstChunkLatencyMs` | 仅在收到首个非空模型输出时记录 |
| `providerResponseId` | Provider metadata 实际返回且格式安全时记录 |
| `usageStatus` | usage 可用状态 |
| `usageSource` | Provider/派生/无 |
| `promptTokens` | 仅有实际值才出现 |
| `completionTokens` | 仅有实际值才出现 |
| `totalTokens` | 仅有实际值或明确允许的派生值才出现 |
| `totalTokensDerived` | 仅 total 由 prompt+completion 派生时为 true |

不记录：

- API Key
- Authorization/Cookie
- Prompt/用户原文
- 模型答案/推理正文
- 异常 message
- 上游原始响应报文

### 6.3 终态唯一性

使用原子 `finished` 标志：

- 同步：调用返回记 SUCCESS，抛错记 ERROR。
- 流式：`onComplete` 记 SUCCESS，`onError` 记 ERROR，Reactor `CANCEL` 记 CANCELLED。
- 同一调用后续终态回调不会重复写第二条。

## 7. Token usage 规则

### 7.1 数据来源

只从：

```text
ChatResponse.getMetadata().getUsage()
```

读取 prompt/completion/total。

不使用字符数、消息长度、经验比例或本地 tokenizer 估算。

### 7.2 状态

| `usageStatus` | 含义 |
|---|---|
| `AVAILABLE` | prompt、completion、total 都有值 |
| `PARTIAL` | 仅部分字段有值 |
| `NOT_RETURNED` | Provider/响应未返回 usage |
| `NOT_SUPPORTED` | 当前 Mock/确定性链路不产生 Provider usage |

来源：

| `usageSource` | 含义 |
|---|---|
| `PROVIDER_METADATA` | 值来自 Provider metadata |
| `DERIVED` | total 由 Provider 返回的 prompt+completion 相加 |
| `NONE` | 无可用 usage |

### 7.3 缺失与 0

- Spring AI 1.1.8 `ChatResponseMetadata` 默认 `EmptyUsage` 的 0 被识别为“未返回”。
- 只有 Provider 明确返回时才可记录 0。
- 缺失字段不写 JSON 字段，不写 null 占位数值，更不补 0。

### 7.4 流式累计

DeepSeek 1.1.8 流式路径通过 `UsageCalculator.getCumulativeUsage` 把累计 usage附着到 chunk metadata。D21 保存最新有效快照，不对多个 chunk 的累计值再次求和。

## 8. 延迟口径

| 指标 | 起点 | 终点 | 用途 |
|---|---|---|---|
| HTTP `elapsedMs` | HTTP 过滤器进入 | HTTP 响应完成 | 完整请求生命周期 |
| MODEL_CALL `elapsedMs` | 模型调用开始/流订阅 | 成功、失败或取消 | 单次逻辑模型调用 |
| `firstChunkLatencyMs` | 模型流订阅 | 首个非空 text/reasoning 输出 | 流式首输出延迟 |

使用 `System.nanoTime()` 计算时长；墙钟只用于 startedAt/finishedAt。

## 9. 配置

| 配置 | 默认值 | 作用 |
|---|---|---|
| `app.access-log.enabled` | true | 控制 HTTP 正文日志和 Controller AOP；关闭后 TraceId/MODEL_CALL 仍保留 |
| `app.access-log.request-id-header` | `X-Request-Id` | 既有请求/响应 ID Header |
| `app.access-log.trace-id-header` | `X-Trace-Id` | 同值响应别名 |
| `app.access-log.request-id-max-length` | 64 | 外部 ID 最大长度，范围 8–128 |
| `app.access-log.sensitive-exact-fields` | message/prompt/completion/content/reasoning_content | Prompt/Completion 精确字段脱敏 |

环境变量示例：

```powershell
$env:REQUEST_ID_MAX_LENGTH = "64"
$env:ACCESS_LOG_ENABLED = "true"
```

关闭正文日志：

```powershell
$env:ACCESS_LOG_ENABLED = "false"
```

关闭后仍返回 `X-Request-Id`/`X-Trace-Id`，并继续产生 `MODEL_CALL` 终态记录。
