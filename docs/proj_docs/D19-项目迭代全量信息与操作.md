## 3. MVC / WebFlux 决策

### 3.1 实际依赖

```text
spring-boot-starter-web 3.5.16
  -> spring-boot-starter-tomcat 3.5.16
  -> spring-webmvc 6.2.19

spring-ai-starter-model-deepseek 1.1.8
  -> spring-ai-deepseek 1.1.8
  -> spring-webflux 6.2.19
  -> spring-ai-client-chat 1.1.8
  -> reactor-core 3.7.19
```

POM 没有声明 `spring-boot-starter-webflux`。`spring-webflux` 和 Reactor 来自 Spring AI 传递依赖。

### 3.2 运行时证据

`MvcStackDecisionTest` 通过真实随机端口启动确认：

- ApplicationContext 是 `ServletWebServerApplicationContext`；
- WebServer 为 Tomcat 10.1.55；
- 容器内没有 Reactive `DispatcherHandler` Bean；
- `reactor.core.publisher.Flux` 和 Spring WebFlux 类仍在 classpath，可支持 Spring AI 流式 API。

### 3.3 决策

保留：

```text
Spring MVC + Tomcat
Flux（模型层）
SseEmitter（MVC 异步响应适配）
```

不增加 WebFlux starter，不迁移全系统。

边界：Servlet 的 HTTP 写出仍包含阻塞式 I/O；不是端到端 WebFlux 非阻塞。Reactor 在上游模型流、超时、取消和分片供给方面保持响应式。

```http

```

响应：

```http

```

请求 DTO 与同步接口相同。接口在基础骨架中已存在，本轮保留路径并完成行为加固。

### 4.3 SSE 事件

| Event | 说明 |
|---|---|
| `start` | requestId、mode、model、sessionId、模板溯源、thinkingEnabled |
| `thinking` | 可选推理增量，只在显式要求展示时发送 |
| `delta` | `seq` 从 0 递增、`content` 为模型实际文本 chunk |
| `citations` | 可选真实检索引用，位于 complete 前 |
| `complete` | 正常结束；包含 seq、mode、model、mocked、totalChars |
| `error` | 受控错误码和固定安全文案；不发送 complete |

delta 的 chunk 不保证等于一个 token、字符或句子。

### 4.4 流开始前错误

参数校验、角色校验、鉴权或缺失会话发生在 SSE 开始前，继续通过统一 JSON 错误返回。已测试：

```json
{
  "code": 4001,
  "msg": "message 不能为空或纯空白",
  "data": null
}
```

## 5. Spring AI 1.1.8 API 核验

实际 `spring-ai-client-chat-1.1.8.jar` 的 `javap` 证据确认：

```java
ChatClientRequestSpec call();
ChatClientRequestSpec stream();

CallResponseSpec.content();           // String
StreamResponseSpec.content();         // Flux<String>
StreamResponseSpec.chatResponse();    // Flux<ChatResponse>
StreamResponseSpec.chatClientResponse(); // Flux<ChatClientResponse>
```

离线测试进一步确认：

- `call()` 返回单次 `content`；
- `stream()` 返回 Flux；
- 创建 `Flux` 时不执行模型调用；
- 首次订阅时才执行 `ChatModel.stream()`；
- 两个 chunk 按到达顺序消费。

## 6. 代码改动

### 6.1 DeepSeek 流式适配

`DeepSeekAiChatService` 新增 `ChatClient`：

```java
this.chatClient = ChatClient.builder(chatModel).build();
```

流式路径：

```java
chatClient.prompt()
    .user(message)
    .stream()
    .content();
```

需要 reasoning/content 分型时：

```java
chatClient.prompt()
    .messages(...)
    .options(DeepSeekChatOptions.builder().model(...).build())
    .stream()
    .chatResponse();
```

同步路径仍使用 `chatModel.call(prompt)`，未改变原接口行为。

### 6.2 客户端断流收口

`ChatStreamController` 修复：

- SSE 写出失败后主动取消上游 `Disposable`；
- 不依赖容器一定触发 `onError`；
- 有部分正文：用户/助手消息按 `INTERRUPTED` 收口；
- 无正文：用户消息按 `FAILED` 收口；
- 主动调用 `emitter.complete()`，释放异步容器资源；
- 正常完成仍保存最终助手全文到 MySQL。

`GlobalExceptionHandler` 增加已提交响应的 I/O 关闭处理，避免客户端断开后再次尝试写 JSON 导致 `No converter for Result with text/event-stream`。
