## 实际依赖与容器结论

| 项 | 实际值 |
|---|---|
| 显式 Web starter | `spring-boot-starter-web` 3.5.16 |
| Servlet 容器 | `spring-boot-starter-tomcat` 3.5.16 |
| MVC 实现 | `spring-webmvc` 6.2.19 |
| Reactive 工具库 | `spring-webflux` 6.2.19，由 Spring AI DeepSeek starter 传递 |
| Reactor | `reactor-core` 3.7.19 |
| 显式 WebFlux starter | 无 |
| 实际上下文 | `ServletWebServerApplicationContext` / Tomcat |
| Reactive `DispatcherHandler` Bean | 无 |

结论：保留 Spring MVC/Tomcat，不增加 `spring-boot-starter-webflux`。

原因：

1. 现有同步接口、Filter、AOP、MySQL 阻塞 DAO 和异常处理均为 Servlet 模型。
2. Spring AI 已通过传递依赖提供 `Flux` 和 `spring-webflux` 所需 API。
3. MVC `SseEmitter` 可桥接 Reactor 流，不需要迁移整个 Web 栈。
4. 双栈迁移会改变过滤器、异常和测试模型，且对同步契约没有收益。

边界：MVC + `SseEmitter` 的容器写出仍包含 Servlet I/O，不是端到端 WebFlux 非阻塞；Reactor 流本身负责按 chunk 供给和取消。

## Spring AI 1.1.8 API 实测

通过实际 `spring-ai-client-chat-1.1.8.jar` 的 `javap` 与离线测试确认：

- `ChatClient.prompt() -> ChatClientRequestSpec`
- `call() -> CallResponseSpec`
- `CallResponseSpec.content() -> String`
- `stream() -> StreamResponseSpec`
- `StreamResponseSpec.content() -> Flux<String>`
- `StreamResponseSpec.chatResponse() -> Flux<ChatResponse>`
- `StreamResponseSpec.chatClientResponse() -> Flux<ChatClientResponse>`
- `stream().content()` 在构造 Flux 时不调用模型；首次订阅时执行。
- 每个 chunk 不保证等于一个 token、字符或完整句子。

证据：

- `spring-ai-1.1.8-chatclient-api.txt`
- `SpringAiChatClientBehaviorTest`
- `d19-dependency-tree.log`

## D19 需求决策

| 需求 | 决策 |
|---|---|
| 流式接口 | 保留 `POST /api/v1/ai/chat/stream`，`text/event-stream;charset=UTF-8` |
| 同步接口 | 保持 `POST /api/v1/ai/chat` 路径、DTO 和 Result 契约 |
| SSE 协议 | `start`、`delta`、可选 `thinking`/`citations`、`complete` 或 `error` |
| 同步模型 | 继续 `ChatModel.call()` |
| 流式真实模型 | 改为 `ChatClient.stream()` |
| MVC/WebFlux | MVC + `SseEmitter`，不迁移 WebFlux |
| 会话 | 复用 MySQL `ChatHistoryService` |
| 正常完成 | 流完成后保存最终助手全文 |
| 上游失败 | SSE `error`，不发送 `complete`，用户消息 `FAILED` |
| 超时 | Reactor `timeout` + SSE 容器兜底，取消上游 |
| 客户端断开 | 取消订阅；有部分正文记 `INTERRUPTED`，无正文记 `FAILED` |
| 日志 | 流式接口排除请求/响应正文访问日志 |
